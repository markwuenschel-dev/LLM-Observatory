# Operations and recovery

## Install and lifecycle

The five backend volumes use a configurable application budget (`OBSERVATORY_MAX_BACKEND_VOLUME_BYTES`). `doctor` measures it read-only; `start` refuses an already-over-budget installed stack before launching services. This is not a Docker-native volume quota, so retention, the Collector queue cap, and the normalized-store byte budget remain the ongoing controls. `status` still probes live API, Collector, and Grafana endpoints when local host state is missing, but reports the missing state separately and remains degraded until `install` reconciles it. Both `status` and `doctor` also inspect the default Compose project's labels and Observatory API bind mount read-only; if a live project references a missing or mismatched generated state path, the result identifies the stale environment file/bind source and recommends reconciliation without stopping or repairing the stack.

Run `observatory install` once from the Observatory checkout. It creates user-level state, a SQLite data directory, a bounded offline spool, a Compose environment file, and a random Grafana admin password. Re-running the command is idempotent and does not touch observed repositories. Use `observatory demo` (or `observatory install --demo`) for an explicit, provider-free, metadata-only walkthrough that populates the dashboards; it is idempotent and should be omitted when the state must contain only real telemetry. Lifecycle commands use a 180-second bounded operation timeout by default so a cold Compose start can complete; override it with global `--timeout` when the host needs a different budget. The normalized SQLite store has a finite 2 GiB default budget (including WAL sidecars); set `OBSERVATORY_MAX_DATABASE_BYTES` in the lifecycle environment to choose another positive byte budget. The installed policy also records a 16 GiB soft budget for the five Docker backend volumes; set `OBSERVATORY_MAX_BACKEND_VOLUME_BYTES` to override it.

`doctor` is read-only and reports whether the state directory, Python runtime, privacy defaults, capability catalog, and Compose surface are available. When Docker is reachable it resolves the installed Compose file and reports exact per-volume usage and total usage for only the five Observatory backend volumes; this is a soft inspection guard, not a Docker quota. Its client probe runs only bounded `--version` checks and records installed/not-installed or host-policy-blocked status; it never starts inference. Installation records the Compose file used, so later lifecycle commands can run from another working directory; `--compose-file` remains available for an explicit override. `start` waits for API, Collector, and Grafana readiness; `stop` manages only the Compose project. `status` reports API, Collector, and Grafana health separately and explicitly says `inference_path: unmanaged/no-proxy`; a reachable but degraded normalizer is not reported as ready and does not imply a provider is unhealthy. `configure <client>` produces a capability-backed plan by default. `configure claude|codex|gemini --apply` can reconcile only their documented user-level telemetry settings; `configure all --apply` applies those native plans and reports partial/unknown clients without blocking inference. `configure --remove` removes only Observatory state unless `--apply` is also supplied. `uninstall --apply` stops the stack and restores only the client keys recorded in the ownership manifest; add `--delete-state` only when the exact installed state directory should also be removed, and add `--remove-volumes` only when durable backend data should be deleted. Without `--apply`, uninstall stops the stack but retains the ownership state for a later cleanup pass. If intake is unavailable, `ingest`, `record-outcome`, and `git-snapshot` use the bounded spool; `flush` replays it after recovery (or into the local store with `--offline`).
`retention --prometheus-days N --tempo-hours N --loki-hours N` updates the installed host policy and reconciles the Compose environment; restart the stack after changing it. Prometheus consumes the time/size values directly; Tempo and Loki expand their duration values at startup. The normalized SQLite event store remains operator-managed and is deleted only through the explicit audited `prune --confirm` path.

For direct API integrations, use the caller-owned `ProviderResponseAdapter` after the application receives a response. Pass `usage_source="provider"` or `usage_source="gateway"` only when that authority is established; omitted usage and auth provenance remain `unknown`. For explicit engineering outcomes, use `record-outcome`, `run-outcome`, or `git-snapshot`; these create correlation records and never assert that a model caused a test, build, commit, or review result. `run-outcome` executes only the argument list supplied by the operator and stores metadata, not stdout/stderr. When the normalized store reaches its byte budget, the API reports degraded readiness and rejects new telemetry; client inference remains unmanaged and unaffected.

Use `scripts/provider-acceptance.ps1` for a real-client gate only when the operator explicitly authorizes the provider command and its token usage. The harness requires the executable and arguments as `-ClientCommand`, uses a unique Compose project with dynamically allocated loopback ports, sets temporary credential-free OTLP endpoint overrides for the client configuration and standard OTLP environment variables for the launched process, runs the client with the requested project as its working directory, fails closed when Git inventory is unavailable, hashes tracked/untracked/ignored repository files before and after the run, and requires a new event to match the configured client, expected provider, non-unknown source, and a unique `llm.observatory.acceptance.run_id` resource marker inherited by the launched process. Pass `-ExpectedSourceName` when the client emits a source name different from its client/provider identity. It is plan-only by default; `-ApplyConfiguration` is an explicit user-level configuration mutation and is never implied, and an applied run must return success with no conflicts. When apply is requested, the harness automatically invokes the ownership-aware remove path in `finally`; any cleanup conflict fails the gate and must be resolved by the operator. The harness never creates an inference proxy, reads provider credentials, or records client stdout/stderr in its result. Example shape (the command itself is intentionally not run by installation):

```powershell
pwsh -NoProfile -File .\scripts\provider-acceptance.ps1 -Client claude -ClientCommand claude,"--print","<operator-authorized acceptance prompt>"
```

Run it from a disposable project or clean worktree. If the harness reports a configuration cleanup conflict, inspect the user-level settings and run `observatory configure CLIENT --remove --apply` only after reviewing the owned-key conflict.

Docker Desktop must be running in Linux-container/WSL2 mode. Default host bindings are loopback-only: API `127.0.0.1:8787`, OTLP gRPC `127.0.0.1:4317`, OTLP HTTP `127.0.0.1:4318`, Collector health `127.0.0.1:13133`, and Grafana `127.0.0.1:3000`. Databases and backend HTTP endpoints remain internal to the Compose network. The host CLI refuses non-loopback API binds unless `run-api --allow-remote` is explicitly supplied, and then requires `--auth-token-file` unless the operator explicitly chooses `--allow-insecure-remote` for a trusted private network. Compose uses that exception only for its internal container-network bind while publishing the API on loopback; it is not a substitute for network authentication. A configured token protects every API data and ingest endpoint with `Authorization: Bearer ...`; health probes remain unauthenticated so service managers can assess liveness without receiving telemetry. Put a token-authenticated remote deployment behind TLS or a trusted private transport; the standalone Python server does not terminate TLS itself.

## Persistence and retention

The API bind-mounts the installed host state directory so the CLI and live service share `data/events.sqlite3`, spool, and secret state. Named volumes are used for Collector queues, Tempo, Loki, Prometheus, and Grafana. The Collector's file-backed queue has a 256 MiB storage cap and fsync-enabled checkpoints; exporter queues are also bounded by item count. Its internal self-metrics endpoint is available only inside Compose at `otel-collector:8888`, while Prometheus scrapes it for queue capacity, queue size, enqueue failures, and send failures; client-exported metrics remain on the separate pipeline endpoint `otel-collector:8889`. The Collector derives a safe project hash from an explicit root/path or common native working-directory resource attributes before deleting raw path attributes, so native OTLP can retain cross-project grouping without persisting filesystem paths. Compose assigns a 30-second stop grace period to the long-lived services so queued telemetry can drain/checkpoint during an intentional stop. Do not use `docker compose down -v` during normal operation. Local state survives container restarts but not disk loss or host destruction.

The initial profile targets 30 days of Prometheus metrics, 30 days of Tempo traces, 14 days of Loki logs, and longer-lived normalized metadata in the SQLite store. These are configurable starting defaults that require host-specific disk measurement before being called production capacity. `doctor` measures the exact named backend volumes and warns at 90% of the configured soft total budget; per-service retention, the 256 MiB Collector queue cap, and the SQLite byte budget remain the actual bounded-growth controls. `backup` emits a SHA-256 checksum and SQLite integrity result. `backup TARGET --full-state` additionally creates a manifest- and checksum-verified host-state archive containing the normalized database snapshot, config, Compose environment, and bounded spool; the Grafana secret is excluded unless `--include-secret` is explicitly supplied. `restore SOURCE --full-state --overwrite` validates every archive member and database integrity before atomically restoring captured host files, preserving the current state through the pre-restore database backup.

For a complete single-host recovery bundle, stop the Compose project and run `backup TARGET --full-state --backend-volumes --include-secret --timeout 300`. Including the Grafana secret is required when backend volumes are archived so a fresh target does not restore a password hash that no longer matches its secret; encrypt the archive before storage. The command resolves the installed Compose project and archives the Collector queue, Tempo, Loki, Prometheus, and Grafana named volumes into the same checksum-verified bundle; it refuses to snapshot a running stack. Restore with `restore SOURCE --full-state --backend-volumes --restore-secret --overwrite --timeout 300` while the target project is stopped. Missing target volumes are created; existing volumes require `--overwrite`, and a volume-bearing archive cannot be silently restored as host-only. Restore stages and validates the archive, snapshots existing host files and named volumes, and rolls those snapshots back if a later file or volume restore fails; a rollback failure is reported as an incomplete recovery rather than a success. The restore command checks the configured target API health URL (default `http://127.0.0.1:8787/healthz`) and refuses a reachable target; use `--api-health-url` when the target stack uses a different port or an unrelated local Observatory occupies the default port. `--compose-file` and `--project-name` are available when the target deployment differs from the installed default. The backend archive uses the pinned Alpine helper already present in Compose and `--pull=never`, so an operator must have that image available locally. Backups must still be encrypted by the host/operator and stored outside the repository.

The runtime gate executes every provisioned panel target through the Grafana Observatory Events (event-time Prometheus compatibility), real Prometheus (Collector self-metrics), Loki, and Tempo proxy paths. A successful query probe proves datasource/query compatibility, not that every panel is visually useful at every screen size; retain a human visual review as a separate release gate.

For an isolated exporter-backpressure proof, run `scripts/queue-saturation-acceptance.ps1`. It launches the pinned Collector image with a two-item, non-blocking queue and an unreachable test exporter on a dynamically allocated loopback port, sends synthetic traces, checks specific queue-full/drop/export-failure evidence, and runs an unrelated inference sentinel. It is a test-only container and removes itself and its temporary configuration by default; it does not use the Observatory Compose project.

The SQLite store contains an append-only ingest ledger, bitemporal field-level measurement facts, outcome observations, and attribution edges in addition to the normalized event payload. Agent behavior counts, source-reported agent/subagent/parent-agent hierarchy, and reliability dimensions (including agent failures, reassessments, and rework loops) are stored as bounded indexed columns and immutable measurement facts; raw activity lists do not cross the default privacy boundary. The application path never updates or deletes those evidence projections. `migrate`, `backup`, `restore`, and `prune --confirm` are explicit administrative commands; migration scripts run in transactions and startup backfills missing projections for legacy event rows. Pruning records an audit action and temporarily removes/reinstates the evidence guards inside one SQLite transaction, then checkpoints/VACUUMs the store when no concurrent writer holds the WAL; a busy checkpoint is reported as deferred rather than hidden. `restore --overwrite` refuses to replace the database while the local API is reachable, takes a pre-restore backup, validates the restored copy, and swaps it into place. No automatic normalized-event age policy is enabled by default; the finite byte budget is the hard disk-growth guard, and operators can use the explicit audited `prune --confirm` path for age-based deletion.

## Failure isolation

| Failure | Observable state | Required behavior |
|---|---|---|
| Collector unavailable | telemetry degraded / exporter diagnostics | Client inference remains on its normal route; bounded adapters spool or drop |
| Store unavailable | API not ready or intake degraded | No provider call is made by the Observatory; CLI falls back to bounded spool |
| Grafana unavailable | dashboard unavailable | API/store/Collector continue independently |
| Malformed event | rejected count and sanitized diagnostic | Valid sibling events continue; raw malformed payload is not retained |
| Queue saturated | bounded queue and retry diagnostics | Telemetry may be lost after bounded retries; monitor Collector queue/storage health and keep inference independent |
| Docker Desktop stopped | engine unavailable | Clients continue; `doctor`/`status` report the Observatory gap |
| Observatory removed | no managed telemetry state | Restore/remove only Observatory-owned client configuration; provider endpoint and credentials remain client-owned |

## Privacy and secrets

Provider credentials are never accepted by the API or Collector. Grafana's generated admin secret lives under the user state directory and is mounted as a Docker secret. The repository contains no provider or Grafana secret. Prompt/completion content and sensitive tool data remain disabled by default. If rich capture is ever added, it requires separate encrypted storage, shorter retention, an audit trail, and canary tests proving the default path remains clean.

## Upgrade posture

Image references are digest-pinned by default and overrideable through explicit `*_IMAGE` Compose variables. `update --check` reads migration state through a SQLite read-only connection and does not open the migrator. `start` reuses the existing local image set and waits for readiness; it does not force a registry-dependent rebuild during ordinary restart/recovery. `update --pull` is the explicit image-refresh path: it reads the current schema without migrating it, creates an integrity-checked SQLite backup under the installed state directory, captures the current Compose image IDs, pulls non-buildable images, rebuilds the local API image, waits for Compose and service readiness, and reports success only after the API, Collector, and Grafana pass bounded post-update gates. If the pull, build, startup, readiness, or migration-state step fails after image mutation, it stops the stack, re-tags the captured image IDs, restores the pre-update SQLite snapshot through a validated temporary copy, and recreates the stack with `--no-build`; the result includes per-step rollback evidence. A successful rollback is reported as degraded because the requested update did not complete. If image capture or any rollback step is unavailable, the command fails closed and retains the pre-update backup for operator-directed recovery. Before an upgrade: run `doctor`, run `docker compose config`, validate the new Collector config against the exact binary, and record the promoted digest/signature before changing the corresponding `*_IMAGE` override. The normalized event contract and migration version must remain compatible with replayed JSONL fixtures.
