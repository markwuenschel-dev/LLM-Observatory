# Privacy and collection policy

The Observatory is metadata-first. The default policy stores event identity, timing, normalized dimensions, status, bounded numeric measurements, provenance, and metadata-only agent behavior while excluding prompt/completion content, raw file/command/test activity lists, sensitive tool arguments/results, credentials, environment values, and raw filesystem paths. Bounded tool names and behavior counts are retained; the underlying payloads are not.

Redaction runs before SQLite persistence, offline spooling, metrics projection, or an optional OpenTelemetry export. It is not a post-processing dashboard filter. The Collector uses its redaction processor plus explicit privacy processors to block sensitive attribute-name patterns and recognizable bearer/API-key values, deletes common prompt/completion/message/tool-content attributes, and replaces log bodies with a fixed redaction marker before fan-out to Tempo, Loki, or the normalizer. It has no debug exporter in the production pipeline. Sensitive keys and recognizable bearer/API-key patterns are replaced with a redaction marker; they are never sent to Grafana or used as provider credentials. Strings are bounded to prevent an accidental large payload from becoming telemetry storage. Unknown provider attributes are dropped by the Collector allowlist; direct host-side adapters still pass through the same default privacy policy before persistence.

Content capture is disabled by default. Enabling it is an explicit operator decision and records `provenance.content_capture = "enabled"`. Even when enabled, credentials and authorization material remain redacted and all values are length-bounded.

The shared Collector boundary is fail-closed: its redaction processor uses an explicit allowlist of normalized metadata keys. When a client supplies a project root/path without a safe project ID, the preceding `transform/project_identity` processor derives a deterministic `local_sha256:` identifier; the raw project root/path/remotes are then removed before export. Unknown attributes, prompts, completions, tool payloads, and credential-shaped fields are removed before export; adding a new provider field requires a reviewed Collector configuration change.

The Observatory derives project identity from Git without adding files or dependencies to observed repositories. Raw roots, worktree paths, and common native working-directory attributes are removed by the default policy after a deterministic local hash is derived; stable project and worktree identifiers remain available for aggregation. Git remotes are sanitized to remove credentials, query strings, and fragments before persistence, and path-shaped project/worktree identifiers are pseudonymized at the same boundary.

Telemetry health is separate from inference health. A failed exporter, store, Collector, or Grafana service may reduce observability, but it must not be placed in a provider request path.
